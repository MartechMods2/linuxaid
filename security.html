Security

Defense is layered, not a single switch.

LinuxAid protects supported backend features with authenticated server calls, row-level access controls, validation, rate limits and client-side session guards.

Authentication

Supabase Auth with PKCE, server-side user verification for AI calls, configurable CAPTCHA and an inactivity session guard.

Database

Row-level security protects user-scoped records. Social writes are validated and rate-limited in PostgreSQL, not only in JavaScript.

Secrets

Provider/API secrets belong in Supabase Edge Function Secrets. Browser config contains only publishable identifiers.

AI

JWT verification, origin allowlist, body limits, daily quota, prompt limits, provider timeout and no-store responses.

Social safety

Reports, user blocks at the data layer, message membership checks and escaped user-generated HTML output.

Terminal safety

Dangerous patterns are blocked in the simulator. High-impact commands in the expanded catalog enter reference mode instead of fake execution.

Account hardening still recommended

Enable Supabase Auth leaked-password protection in the project dashboard, keep CAPTCHA/rate-limit settings reviewed, and use branch protection plus code review before production merges.

Found a vulnerability?

Do not post passwords, tokens, private keys or working exploit secrets in a public discussion. Use GitHub's private vulnerability reporting/security advisory flow for the repository when available, and provide the smallest reproducible description needed to investigate.
