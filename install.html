Before any full installation

  1. Back up files you cannot replace. A Linux installer can erase an entire disk if the wrong target is selected.
  2. Record recovery keys for disk encryption such as BitLocker before resizing or changing boot settings.
  3. Download the ISO only from the distribution's official site and verify its checksum when the project publishes one.
  4. For a desktop installer, use an 8 GB or larger USB drive. Writing an ISO destroys the existing contents of that USB.
  5. Know your CPU architecture: most PCs are x86-64/amd64; many phones, Raspberry Pi boards and Apple Silicon Macs are ARM64/aarch64.

Beginner rule: if you are unsure about partitioning, use a virtual machine or WSL first.

PC / laptop: bootable USB installation

1. Pick a distribution

Ubuntu / Linux Mint

Good first desktop choice, broad hardware/software support.

Fedora Workstation

Modern desktop stack and strong developer tooling.

Debian

Conservative, stable base for desktops and servers.

Arch Linux

Manual and educational; best after you understand disks, bootloaders and networking.

Kali Linux

Security testing distribution. Prefer a VM unless you specifically need it as a primary system.

Alpine / server distros

Minimal environments, containers and servers rather than a typical beginner desktop.

2. Create installer media

Download the ISO, then use an image writer such as Rufus on Windows, GNOME Disks/KDE ISO Image Writer on Linux, or balenaEtcher on supported platforms. Do not simply copy the ISO file onto the USB.

3. Boot the USB

Restart and open your firmware boot menu (the key varies by manufacturer, commonly F12, F9, Esc or Del). Choose the USB's UEFI entry. If the distro offers a “Try” or live mode, use it first to test Wi-Fi, audio, display, keyboard and touchpad.

4. Choose an install style

  • Erase disk: Linux becomes the only OS. Everything on the selected disk can be deleted.
  • Install alongside: dual-boot with your current OS when the installer safely supports it.
  • Manual partitioning: advanced. Typical UEFI installs use an EFI System Partition plus a Linux root filesystem; swap may be a file, partition or zram depending on distro.

5. Finish and verify

Create your user account, reboot, remove the installer USB, install updates, then confirm networking, graphics, sleep, Bluetooth and audio. Keep the live USB until you know the installation boots reliably.

Windows: WSL 2

For development, command-line Linux and many server tools, WSL is usually safer and faster than repartitioning a Windows PC.

# PowerShell as Administrator
wsl --install

# See distributions available from Microsoft
wsl --list --online

# Install a specific one
wsl --install -d Debian

# Check installed distros and WSL version
wsl --list --verbose

Restart when Windows asks. On first launch, the Linux distribution creates its own Linux username/password. Windows drives are normally visible under /mnt/c, but Linux development projects generally perform better inside the Linux filesystem.

Virtual machine: safest full Linux desktop practice

  1. Install a hypervisor such as VirtualBox, VMware Workstation/Fusion, UTM on supported Macs, or Hyper-V where appropriate.
  2. Create a VM and choose the correct x86-64 or ARM64 ISO for your host/hypervisor.
  3. For a beginner desktop, start around 4 GB RAM, 2 CPU cores and 30–50 GB dynamically allocated storage when your hardware permits.
  4. Boot the ISO inside the VM and install normally. The virtual disk is a file, so mistakes normally stay inside the VM.
  5. Take a snapshot before risky experiments so you can roll back.

Virtualization is ideal for Kali, Arch practice, server labs, bootloader exercises and testing commands you should not try on your daily computer.

Android: Termux + PRoot, no root required

Install Termux from F-Droid or its official GitHub releases, not an abandoned third-party build. Then:

pkg update && pkg upgrade
pkg install proot-distro
proot-distro list

# Example
proot-distro install debian
proot-distro login debian

# Leave the distro
exit

This gives you a Linux userspace, not a replacement Android kernel. Hardware access, systemd, Docker and low-level networking may behave differently from a normal Linux machine. That limitation is expected and is safer than rooting a phone just to learn Linux.

Mac: Intel vs Apple Silicon

Intel Mac: Linux can often be installed by the same USB workflow as a PC, but Apple-specific Wi-Fi, trackpad, firmware and boot behavior should be checked for the exact model first.

Apple Silicon (M-series): ordinary x86 PC ISOs are not appropriate. Use an ARM64-compatible virtual machine for the easiest route, or a project specifically supporting Apple Silicon hardware. Verify support for your exact Mac before changing disk partitions.

ChromeOS, iPhone/iPad and special hardware

ChromeOS

Supported Chromebooks can enable the built-in Linux development environment (Crostini), which creates a Debian-based container without replacing ChromeOS. Full firmware replacement is a different, device-specific and higher-risk process.

iPhone / iPad

iOS/iPadOS do not provide a normal supported path to replace the operating system with desktop Linux. Use SSH to a Linux machine, a shell/emulation app, or a remote development environment instead. LinuxAid does not recommend jailbreaking a device simply to learn command line basics.

Raspberry Pi / ARM boards

Use an image built specifically for that board and architecture, usually written to microSD or NVMe with the project's official imaging tool. Generic PC installers may not include the required boot firmware or device tree.

After installation: first checks

uname -a
cat /etc/os-release
ip addr
ip route
df -h
free -h
systemctl --failed

Then update using your distro's package manager: Ubuntu/Debian use apt, Fedora/RHEL use dnf, Arch uses pacman, Alpine uses apk. Open the LinuxAid Terminal V8 and type debug network, debug disk or debug service when something goes wrong.
