Windows: WSL 2

Open PowerShell as an administrator, then run:

wsl --install

Restart if Windows asks you to. To see available distributions:

wsl --list --online

Example:

wsl --install Ubuntu-24.04

Use WSL when your goal is coding, shell learning, Git, package management and Linux development without changing partitions.

Official Ubuntu WSL guide
Virtual machine route
  1. Download an ISO only from the distro's official site.
  2. Install a hypervisor such as VirtualBox, VMware, Hyper-V or UTM.
  3. Create a VM with enough RAM, CPU and disk space for the distro.
  4. Attach the ISO, boot the VM and follow the distro installer.
  5. After installation, remove/eject the ISO and update the new Linux system.

Good default: 4 GB RAM, 2 CPU cores and 30–50 GB virtual disk for a desktop distro if your host has enough resources.

PC: USB, dual boot or full install
Before changing partitions: back up important files and confirm you can restore them.
  1. Choose a distro and download its ISO from the official website.
  2. Verify the ISO checksum when the distro publishes one.
  3. Create a bootable USB with Rufus, balenaEtcher, Ventoy or the distro's recommended writer.
  4. Restart the PC and open the one-time boot menu or UEFI/BIOS boot menu.
  5. Boot from the USB and choose the live/trial mode first when available.
  6. Confirm Wi‑Fi, keyboard, graphics, audio and storage detection.
  7. Start the installer. Choose Install alongside only when the installer clearly detects your existing OS and you understand the partition plan.
  8. For a full-disk Linux install, confirm the correct disk before accepting any erase option.
  9. Create a strong user password and enable disk encryption when appropriate.
  10. After first boot, run system updates and install drivers/firmware from trusted sources.

Do not guess with partitions

If the installer shows unexpected partitions, missing Windows, BitLocker warnings, RAID/RST storage, or an unknown disk layout, stop and research that exact device before continuing.

Android: three levels

1. Termux

Best beginner route. Android stays intact while you get a Linux-like shell and package manager. Prefer the official Termux GitHub/F-Droid distribution path.

Official Termux project

2. Kali NetHunter Rootless

Kali provides a rootless edition for stock, unmodified Android devices. This is safer than unlocking/rooting a phone just to learn Linux.

Official Rootless guide

3. Native mobile Linux

Projects such as postmarketOS support selected phones and tablets. Device support varies, so check the exact model and feature status before flashing.

postmarketOS devices

Advanced warning: bootloader unlocking, custom kernels, custom recovery and rooted NetHunter installs can wipe data, break banking/DRM apps, reduce device security or brick unsupported devices. Follow the exact device documentation.

Mac

For most learners, run Linux in a VM first. Intel Macs and Apple-silicon Macs have different native-install paths, and support depends on the model. Do not apply an Intel dual-boot guide to Apple silicon.

If your goal is terminal learning, development or server administration, virtualization or a remote Linux machine is usually the cleanest option.

Distro chooser

Ubuntu / Linux Mint

Strong beginner choices with large communities and broad hardware support.

Fedora

Good for modern Linux development and newer desktop technologies.

Debian

Stable foundation with a huge package ecosystem; excellent for servers and experienced beginners.

Arch

Best when you intentionally want a hands-on installation and maintenance learning experience.

Kali

Security-focused. Use it for authorized labs and learning, not as the automatic choice for a first daily-driver desktop.

Lightweight desktop

For older hardware, prefer XFCE or LXQt editions and keep background services modest.

After installation
# Debian / Ubuntu
sudo apt update && sudo apt upgrade

# Fedora
sudo dnf upgrade

# Arch
sudo pacman -Syu

Then set up backups, automatic security updates where appropriate, a firewall, SSH carefully, and a non-root daily account. Never copy random commands into a root shell just because a tutorial says so.
